# Terraform: Talos machine configs (home-cluster-1)

Manages the Talos machine configurations (controlplane + worker) and the
cluster secrets as code with the `siderolabs/talos` provider (v0.11.0), so that
OS/cluster-level settings no longer live only in `home-cluster-1-config/` YAML
files.

## How secrets are handled

The `talos_machine_secrets.this` resource holds the live cluster CA material,
tokens and cluster id/secret. It was **imported** from the cluster's existing
secrets bundle — it is not generated by this configuration.

The bundle itself stays outside the repo in `home-cluster-1-config/secrets.yaml`
(it is the input to `terraform import` only). Do not delete it: it is the
disaster-recovery copy of the CA material.

## Flow

```sh
cd prod
terragrunt init
terragrunt plan
terragrunt apply
```

Apply generated configs to nodes (diff against what's running first):

```sh
talosctl --talosconfig <talos_config> -n 192.168.1.107 apply-config --file <machine_config_controlplane> --mode try
talosctl --talosconfig <talos_config> -n 192.168.1.108 apply-config --file <machine_config_worker> --mode try
```

Retrieve client configs:

```sh
terragrunt output -raw talosconfig > ../../../../../home-cluster-1-config/talosconfig
terragrunt output -raw kubeconfig  > ../../../../../home-cluster-1-config/kubeconfig
```

## What is still manual

- `config_patches` only override the installer image and the control-plane
  install disk. Everything else (UKI cmdline flag, disk quotas, kubePrism,
  hostDNS, kubelet seccomp, PodSecurity admission, audit policy, node labels,
  discovery registries, subnets, HostnameConfig) comes from the Talos v1.13
  contract defaults and matches the live nodes.
- Low-power kernel args and the worker's `iscsi-tools` extension are baked into
  the Image Factory schematics, not into config patches. Changing them requires
  re-minting the schematic and upgrading the nodes to the new image.
- `certSANs` is empty; add SANs if the control plane is ever reached by
  hostname instead of `192.168.1.107`.
- `talos_machine_configuration_apply` is intentionally not used yet. Adding it
  makes `apply` push config to live nodes; validate the generated config with
  `--mode try` before enabling it.

## Migration (already done)

The live cluster was adopted in this order:

1. `talosctl gen secrets --from-controlplane-config home-cluster-1-config/controlplane.yaml -o home-cluster-1-config/secrets.yaml`
   (derives the exact live bundle — CA, tokens, cluster secret).
2. `terragrunt import talos_machine_secrets.this /abs/path/to/secrets.yaml`
3. Diff the generated `machine_config_*` outputs against the plaintext YAML,
   then `apply-config --mode try` on each node before applying for real.
